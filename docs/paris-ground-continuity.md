# ノートルダム周辺の地面のつながり

雨の三人称開始位置で白い面になっていたのは、地形の石畳表示が大聖堂から100〜130mで元の単色地形に戻る設定だったため。開始位置は大聖堂から約136m離れている。推定舗装の範囲を200mに広げ、200〜240mで元の色に戻す。元データに舗装の種類が記録されていない箇所の外観は推定であり、実測舗装ではない。

近景地形の石畳は既存の歩道と同じ写真素材、世界座標のタイル幅、色、粗さ、濡れマスクを使用。雨の反射が一様な白い鏡面にならないよう、道路・石畳・護岸など11材質の濡れた状態の粗さを調整した。

地形と歩道は別の三角形から高さを補間しており、境界に数cm〜1m以上の差がある。200m付近以内の歩道境界では、20cm未満の差を地形の表示メッシュ側で合わせる。また、歩道が30cm以上高い箇所では下の地形を残し、視線が抜ける灰色の穴を抑える。道路・公園・水域など他の地物と重なる部分は除外する。緯度経度、元の地形、歩道の形状と既存の衝突判定は保持している。

再生成: AIWorldのプレビューとエディタを閉じ、 `powershell -NoProfile -ExecutionPolicy Bypass -File .\unreal\scripts\Build-ParisGroundContinuity.ps1` を実行。固定データから表示メッシュを生成し、必要な材質と雨のレイヤーを再構築する。元のアセットは `backups/paris-ground-assets-*` に保存する。

UE 5.8で材質と表示メッシュを保存し、D3D12の雨天・三人称・同じ出発視点で比較した。修正後は手前に石畳が表示され、灰色に抜けていた部分にも地形が見える。[修正後](paris-ground-continuity-after.png)、[修正前](paris-rain-preview.png)。

元の衝突形状は変更していないため、大きな高低差がある歩道の境界では、表示上も細い暗い段差が残り、歩行時に乗り越えられない可能性がある。高さ差が大きい場所を自然な勾配と歩行可能な衝突にするには、地形と歩道の形状を一緒に再生成する必要がある。今回の補正は測量値の修正ではない。

自動検証では地形データを変更せず同じ結果を再生成できること、道路・公園・河川との重複が許容範囲内であること、表示地形の小さな高さ補正の上限を確認した（Python 1件成功）。UE内では地形表示と元の衝突の保持、雨の動作、環境音とミュートを検証し、3件が成功。[UE検証ログ](paris-ground-continuity-tests.txt)。大きな段差を歩いて越えられることは検証していない。
